# Native ARM64 and x86-64 event RNG portability v0.1

## Purpose

The existing Rust and Random123 parity checks establish a finite reference comparison, but all hosted qualification had run on x86-64. This contribution adds native AArch64 execution and a fixed byte-level fixture shared by both architectures.

## Fixed portability corpus

The example emits a host-independent text corpus containing:
- Random123 all-zero and mixed Philox4x64-10 known-answer outputs;
- a fixed EventAddress block using a nontrivial key and packed event code;
- the exact binary64 bit pattern for the top-52-bit open-uniform conversion;
- a canonical dynamic BirthKey-derived SubjectId;
- the canonical serialized dynamic-lineage receipt for that birth.

The expected output is checked into tests/reference/event-rng-portability-v1.txt. Each architecture compares the complete generated bytes to that fixture, not merely to a locally generated digest.

## Hosted runners and compiler

- x86-64: ubuntu-24.04.
- ARM64: ubuntu-24.04-arm.
- Cross-architecture common toolchain: Rust/Cargo 1.100.0.
- Existing x86-64 workflow also checks the same fixture on Rust 1.99.1 and Rust 1.101.0-beta.1.

The ARM job runs natively on AArch64; it does not use QEMU or cross-compilation as a substitute for executing the code on the target architecture.

## Qualification boundary

A byte-for-byte match demonstrates that the tested Philox core, fixed EventAddress mapping, uniform bit conversion, canonical dynamic BirthKey derivation and receipt serializer produce the same outputs on the tested x86-64 and AArch64 hosts for this corpus.

It does not prove all possible inputs, all Rust versions, all targets, GPU parity, or whole-application numerical equivalence. The broader property-based/reference corpus and future platform matrix remain relevant.

## Industry comparison

Compiler test suites often establish correctness on supported target platforms, while RNG parity suites often validate a finite reference corpus. This change combines both for the actual Luminous semantic address stack and adds a checked-in, replayable byte fixture. It is a portability gate, not a performance comparison or SOTA claim.
