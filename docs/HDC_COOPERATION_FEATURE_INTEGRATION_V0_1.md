# HDC cooperation example integration v0.1

**Status:** feature-wiring proposal. The default build remains free of the optional HDC dependency until the `consciousness-hdc` feature is explicitly enabled.

## What already existed

The HDC adapter source was already present at `src/hdc_context.rs`. It contains:
- `HdcConsciousnessContext` over 16,384-dimensional `ContinuousHV` state;
- an `HdcLtcUnifiedNetwork` encoder;
- deterministic seed-based basis-vector initialization;
- state-to-seven-component input mapping;
- context stepping and a norm-derived output scalar;
- unit tests for determinism, state evolution, input clamping, and temporal memory.

The initial compile failure was not an absent source file. It was a missing integration contract:
- no optional `symthaea-core` dependency in the package manifest;
- no `consciousness-hdc` feature;
- no `hdc_context` module export under that feature;
- no Cargo example target requirement for `hdc_cooperation`.

## Integration change

The branch adds:
- exact optional dependency `symthaea-core = 0.5.1`, with default features disabled;
- opt-in feature `consciousness-hdc = ["dep:symthaea-core"]`;
- `#[cfg(feature = "consciousness-hdc")] pub mod hdc_context;`;
- `[[example]] hdc_cooperation` with `required-features = ["consciousness-hdc"]`.

This means default `cargo check --all-targets` does not compile the HDC example or activate the HDC dependency. An explicit HDC command must enable the feature:

```sh
cargo check --example hdc_cooperation --features consciousness-hdc
cargo test --lib --features consciousness-hdc
cargo run --release --example hdc_cooperation --features consciousness-hdc
```

The dependency is pinned to a release version. It is not a floating Git branch or a copied implementation. Its Cargo.lock delta must be generated by Cargo and reviewed before the branch is considered complete.

## Qualification

A dedicated hosted job:
1. installs exact Rust/Cargo 1.99.1;
2. resolves the optional dependency with Cargo (without `--locked` for the first resolution);
3. compiles the HDC example;
4. runs library tests with the HDC feature;
5. captures the dependency tree and generated Cargo.lock as a short-lived artifact.

The lockfile artifact must be inspected and committed as a separate generated-file change. After that, the qualification job must be changed to `--locked` and rerun on the exact resulting HEAD. This proposal alone does not claim the HDC feature passes.

## Scientific and semantic limits

The integration only wires the existing adapter. It deliberately does not alter the algorithm or claim a new result.

A follow-up audit is required before the experiment is treated as a validated HDC-versus-scalar study:
- `HdcConsciousnessContext::step` accepts a harmony vector, but the current body does not use it to build the input encoding.
- The adapter constructs `harmony_basis`, but the current code does not use those basis vectors in the update.
- `phi_from_thought` currently derives its scalar from the output-vector norm; the harmony argument is unused, and the docstring's integration-times-complexity explanation is not what the implementation presently computes.
- The scalar condition and HDC condition must be checked for matched input histories, action authority, energy costs, and reset semantics.
- Each seed must be paired across conditions; outputs should include raw trajectories and per-agent state so the analysis can test more than endpoint averages.

Therefore:
- `Hdc` feature wired != HDC representation validated.
- A bounded norm scalar != IIT Φ.
- An executable example != replicated scientific finding.
- Any observed performance or survival change must be tested against the scalar baseline with matched seeds and preregistered metrics.

## Next benchmark tranche

Once the feature compiles and the Cargo.lock change is committed:
- Compare scalar vs HDC context throughput at 12 agents × 5,000 ticks and across smaller/more realistic test scales.
- Record per-tick wall time, p50/p95 update latency, peak RSS, allocations, bytes copied, and per-agent HDC context memory.
- Separate network construction from steady-state update cost.
- Add a no-HDC baseline that performs the same vector and physics operations without LTC evolution.
- Run at least 30 paired seeds for exploratory comparisons; use 100+ paired seeds for a more stable effect estimate if compute permits.
- Report survival, convergence, resource efficiency, and clustering separately. Do not optimize or select a single favorable endpoint after seeing results.
- Compare HDC output norms and similarities against independent numerical invariants and perturbation controls.

The aim is to evaluate when the HDC/LTC representation adds measurable value to the physical model, not to assert that the high-dimensional representation is inherently superior.

## Reference

The reusable implementation is from the published `symthaea-core` crate. Its public API exposes `ContinuousHV` and the HDC-LTC unified network; the current integration uses those APIs directly rather than duplicating them. Docs: https://docs.rs/symthaea-core/0.5.1/symthaea_core/
